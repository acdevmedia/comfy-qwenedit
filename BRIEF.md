# Qwen Image Edit 2511 bundle maintenance brief

Build the Runpod ComfyUI bundle for `acdevmedia/comfy-qwenedit`, publishing `ghcr.io/acdevmedia/qwenedit-comfyui:2511` and immutable per-commit tags through GitHub Actions. Do not build Docker images locally; this workstation has neither the storage nor the CPU budget.

Qwen-Image-Edit-2511 runs on ComfyUI's **native** support (`TextEncodeQwenImageEditPlus`, `CFGNorm`, `ModelSamplingAuraFlow`). No custom node and no Diffusers pipeline. Keep it that way.

The model is **Apache 2.0** and ungated, so `HF_TOKEN` is optional; do not reintroduce a hard token requirement. Weights come from Comfy-Org's ComfyUI-split repositories and the `lightx2v` Lightning LoRA, pinned by revision, size and SHA256.

It is an **editing model with no text-to-image mode**: every workflow needs an input image, and the README says so rather than shipping a text-to-image graph the model was not built for.

Packaged settings follow the publishers: Lightning is the 8-step LoRA at strength 1.0, 8 steps and CFG 1.0 (LightX2V's `enable_cfg: false`); standard is the model card's 40 steps with the maintainer's CFG 3.5 and a full negative prompt. Both use `euler`/`simple`, shift 3.1 and CFGNorm 1.0.

Workflows are generated by `scripts/build-workflows.py` in API and UI form from one spec; edit that, not the JSON. The generator asserts link integrity and that both forms agree.

Use source validation locally, image build plus CPU graph-schema checks in Actions, and real Runpod GPU generation before claiming runtime behaviour or output quality. `README.md` and `docs/VALIDATION.md` describe the current deployment state.
